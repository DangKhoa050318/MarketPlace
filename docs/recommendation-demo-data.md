# Recommendation Demo Data

[`backend/scripts/seed-recommendation-demo-data.sql`](../backend/scripts/seed-recommendation-demo-data.sql)
provides deterministic development data for `FEATURE-STP-03`.

The file is an opt-in SQL script outside Flyway's `db/migration` directory. It
is never applied automatically when the backend starts and does not create or
modify any migration.

## What is seeded

| Area | Dataset | Expected behavior |
| --- | --- | --- |
| Similar products | Metadata for 20 storefront products, four extra active SKUs, two eligibility edge products | Category, brand, attributes and price ranges all influence scoring; hidden products and products without an active SKU are filtered |
| Best sellers | 48 recent valid orders, eight excluded-status orders and four expired orders | Valid recent status rows rank; `PENDING`, `CANCELLED` and expired rows do not |
| Co-purchased | 36 Dell workspace bundles and 12 Samsung phone bundles | Dell pairs rank Logitech (36), Keychron (28), LG (18), Anker (12), Bose (8) |
| Co-viewed | Anonymous session cohorts, repeated views, user-only actors and expired views | Dell pairs rank Logitech (45), Keychron (35), LG (25), Bose (15), Pixel (5); repeat views do not inflate counts |
| Attribution | Similar and home-best-seller impression/click funnels plus cart and trusted purchase events | Stable request IDs correlate each funnel stage |

All demo identities use the existing `demo_customer_XX` accounts. Event
properties contain only test labels and no personal data.

## Find stable IDs

Product IDs are generated by the database, so resolve them from the stable
slugs before calling the API:

```sql
SELECT id, slug, name
FROM products
WHERE slug IN (
    'dell-xps-14-9440',
    'samsung-galaxy-s24-ultra',
    'playstation-5-slim'
)
ORDER BY slug;
```

## API scenarios

Replace `<dell-id>`, `<samsung-id>`, `<ps5-id>` and `<computer-category-id>`
with values from the database.

```http
GET /api/v1/recommendations?placement=PRODUCT_DETAIL_SIMILAR&productId=<dell-id>&limit=12
GET /api/v1/recommendations?placement=PRODUCT_DETAIL_CO_VIEWED&productId=<dell-id>&limit=12
GET /api/v1/recommendations?placement=PRODUCT_DETAIL_CO_PURCHASED&productId=<dell-id>&limit=12
GET /api/v1/recommendations?placement=PRODUCT_DETAIL_CO_VIEWED&productId=<samsung-id>&limit=12
GET /api/v1/recommendations?placement=PRODUCT_DETAIL_CO_VIEWED&productId=<ps5-id>&limit=12
GET /api/v1/recommendations?placement=HOME_BEST_SELLERS&limit=12
GET /api/v1/recommendations?placement=CATEGORY_BEST_SELLERS&categoryId=<computer-category-id>&limit=12
```

The precise `SIMILAR` score is intentionally richer than an exact fixture
ranking because several signals contribute. The co-viewed and co-purchased
counts above are deterministic unless more local events/orders are added.

## Inspect the attribution funnels

```sql
SELECT
    properties ->> 'seedScenario' AS scenario,
    event_type,
    COUNT(*) AS event_count
FROM analytics_events
WHERE properties ? 'seedScenario'
GROUP BY properties ->> 'seedScenario', event_type
ORDER BY scenario, event_type;
```

For the similar-product funnel, the seeded conversion counts are:

| Stage | Count |
| --- | ---: |
| `RECOMMENDATION_IMPRESSION` | 24 |
| `RECOMMENDATION_CLICK` | 14 |
| `ADD_TO_CART` | 10 |
| `PURCHASE` | 8 |

Inspect one complete correlated journey:

```sql
SELECT
    recommendation_request_id,
    event_type,
    product_id,
    variant_id,
    position,
    quantity,
    order_id,
    occurred_at
FROM analytics_events
WHERE recommendation_request_id =
      md5('rec-v17:similar-request:1')::uuid
ORDER BY occurred_at;
```

## Loading the data

Start the local PostgreSQL service, then run the script explicitly:

```powershell
cd backend
Get-Content -Raw scripts/seed-recommendation-demo-data.sql |
    docker compose exec -T postgres psql -U postgres -d marketplace_db
```

If your Compose service is named differently, use the PostgreSQL service name
from `docker-compose.yml`.

## Resetting local data

The script uses stable identifiers and conflict checks, so it is safe to run
again against the same local database. For a completely clean reset in
development, recreate the local database/volume and let the existing migrations
run before executing this standalone script again.
